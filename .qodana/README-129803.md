## 1. Cheiro de código selecionado

O cheiro de código escolhido foi **Long Parameter List**, do catálogo de Martin Fowler.

Este cheiro ocorre quando um método recebe um número excessivo de parâmetros, podendo dificultar a sua compreensão, utilização e manutenção.

Para a sua deteção foi utilizada a ferramenta Qodana, integrada no GitHub Actions, através da inspeção `ParametersPerMethod`.

## 2. Tabela de mapeamento

| Informação | Descrição |
|---|---|
| Cheiro de código (Fowler) | Long Parameter List |
| Inspeção no IntelliJ | Method with too many parameters |
| ID da inspeção | ParametersPerMethod |
| Métrica | PAR — Número de parâmetros por método |
| Valor-limite por omissão | 5 parâmetros |
| Limitações | A inspeção utiliza um limite absoluto, não permitindo reproduzir diretamente critérios relativos ao sistema. Também não avalia a complexidade ou a necessidade de cada parâmetro. |

## 3. Configuração do Quality Gate

Foi configurado um workflow no GitHub Actions para executar automaticamente o Qodana Community e identificar métodos com mais de 5 parâmetros.

Foram criados os seguintes ficheiros:

- `.github/workflows/qodana-smell-129803.yaml`
- `qodana-129803.yaml`
- `.qodana/profiles/profile-129803.yaml`

O Quality Gate foi configurado para falhar quando é detetada pelo menos uma violação da inspeção selecionada.

## 4. Testes realizados

### Teste 1 — Introdução do cheiro de código

Foi criada a classe `LongParameterSmell129803`, contendo o método `calcularSoma()` com 6 parâmetros.

Como o limite configurado era de 5 parâmetros, o Qodana identificou uma violação e o Quality Gate falhou corretamente.

**Resultado:** Falha — 1 problema identificado.

**Ligação para a execução:**

https://github.com/LETI-129803/Battleship2/actions/runs/42519367971

### Teste 2 — Correção do cheiro de código

O método `calcularSoma()` foi alterado para receber apenas 5 parâmetros.

Após a correção, o Qodana não identificou novas violações da inspeção selecionada e o Quality Gate passou com sucesso.

**Resultado:** Sucesso — 0 problemas identificados.

**Ligação para a execução:**

https://github.com/LETI-129803/Battleship2/actions/runs/42520589556/job/128852998517?pr=16

## 5. Reflexão

O Qodana identificou corretamente o método com 6 parâmetros e deixou de sinalizar a violação após a sua correção. Nos testes realizados não foram observados falsos positivos, embora possam existir falsos negativos quando métodos com até 5 parâmetros apresentam problemas de desenho. Os resultados dependem do valor-limite configurado, uma vez que a sua alteração pode aumentar ou diminuir o número de violações identificadas. Comparativamente às estratégias quantitativas descritas no livro *Object-Oriented Metrics in Practice*, esta inspeção apresenta limitações por utilizar um limite absoluto e não considerar critérios relativos ao sistema.
