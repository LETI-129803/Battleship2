## 1. Convenção de nomes selecionada

A convenção de nomes escolhida foi **ConstantName**, disponibilizada pela ferramenta Checkstyle.

Esta regra verifica se as constantes declaradas no código Java respeitam uma convenção de nomenclatura, utilizando letras maiúsculas e underscores (`_`) para separar palavras.

A regra selecionada é diferente da `MethodName`, utilizada por outro elemento do grupo.

## 2. Configuração da regra

Foi criado o ficheiro `Checkstyle/checkstyle-129803.xml`, que contém a configuração da inspeção.

| Propriedade | Valor |
|---|---|
| Ferramenta | Checkstyle |
| Regra | ConstantName |
| Identificador | ConstantName |
| Padrão utilizado | `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$` |
| Comportamento esperado | Rejeitar constantes cujos nomes não respeitem o padrão |

O padrão exige que o nome comece por uma letra maiúscula e utilize apenas letras maiúsculas, números e underscores nas posições permitidas.

## 3. Integração com GitHub Actions

Foi criado o workflow `.github/workflows/checkstyle-129803.yml` para executar automaticamente o Checkstyle nos Pull Requests.

A execução utiliza o Maven Checkstyle Plugin e a configuração personalizada da regra `ConstantName`.

Quando é identificada uma violação, o comando termina com falha, permitindo utilizar o resultado como Quality Gate.

## 4. Testes realizados

### Teste 1 — Introdução de uma violação

Foi criada a classe `CheckstyleConstantName129803.java` com a seguinte constante:

```java
public static final int maxTentativas = 10;
```

O nome `maxTentativas` não respeita a convenção configurada, uma vez que contém letras minúsculas.

**Resultado:** O Checkstyle identificou a violação da regra `ConstantName` e o Quality Gate falhou.

**Evidência — execução com falha:**

https://github.com/LETI-129803/Battleship2/actions/runs/42525776333/job/128868939913?pr=19

### Teste 2 — Correção da violação

A constante foi corrigida para:

```java
public static final int MAX_TENTATIVAS = 10;
```

Após a alteração, o nome passou a respeitar a convenção estabelecida.

**Resultado:** O Checkstyle executou com sucesso e o Quality Gate passou.

**Evidência — execução com sucesso:**

https://github.com/LETI-129803/Battleship2/actions/runs/42526605142/job/128871502630?pr=19

Os dois testes foram realizados no Pull Request #19, criado especificamente para validar o funcionamento do Quality Gate, sem integrar o código de teste na branch principal.

## 5. Reflexão

A utilização do Checkstyle permitiu verificar automaticamente o cumprimento da convenção de nomes escolhida. A ferramenta identificou corretamente a constante `maxTentativas` como uma violação e deixou de apresentar esse erro após a alteração para `MAX_TENTATIVAS`. A integração com GitHub Actions demonstrou que é possível detetar estas situações antes da integração de alterações no projeto. Contudo, a regra verifica apenas a estrutura dos nomes e não permite avaliar se estes são suficientemente claros ou adequados ao contexto. A automatização contribui para melhorar a consistência do código e reduzir erros relacionados com convenções de desenvolvimento.
