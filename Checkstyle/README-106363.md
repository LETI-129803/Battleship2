## 3. Reflexão Crítica

A inspeção do Checkstyle com a regra `MemberName` permite assegurar de forma automatizada que todos os atributos (variáveis de instância) das classes seguem a convenção *lowerCamelCase*, ou seja, começam com letra minúscula e são seguidos de letras e/ou dígitos. Esta abordagem garante uniformidade na nomenclatura dos campos entre todos os membros da equipa e previne inconsistências como o uso de *snake_case* ou *PascalCase* em atributos.

No entanto, a ferramenta apresenta limitações inerentes à sua natureza puramente léxica. Não avalia a qualidade semântica dos nomes: um atributo chamado `a`, `temp` ou `d` cumpre formalmente a regra, mas viola o princípio do código auto-documentado. Além disso, a regex `^[a-z][a-zA-Z0-9]*$` não permite o uso de underscore, o que exclui padrões como `my_variable` — uma escolha válida em alguns contextos, mas incompatível com a convenção Java padrão.

A integração no GitHub Actions como quality gate garante que qualquer código que não respeite a convenção é rejeitado automaticamente antes de ser mergeado na branch principal, reforçando a disciplina de estilo de forma contínua e sem dependência de revisão manual.
